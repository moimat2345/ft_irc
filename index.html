#constraints

Topic: rules that set the grade to 0 if broken — read before writing a single socket call.
Grade = 0 if any of these happen The program crashes or quits unexpectedly, for any reason, including running out of memory.
Grade = 0 Any read/recv/write/send happens on a fd that wasn't reported ready by the single poll().
Grade = 0 Deciding what to do next based on errno after a recv/send (e.g. retrying on EAGAIN).

Everything else that's mandatory

  • BUILD Makefile with NAME, all, clean, fclean, re, no needless relinking.
  • LANG C++98, compiled with -Wall -Wextra -Werror, no Boost, no external libs.
  • I/O No forking. Every socket non-blocking. Exactly one poll()/select()/kqueue()/epoll() for everything — accept, read, and write.
  • NET TCP/IP (v4 or v6). Must handle messages arriving split across several packets.
  • FEATURES PASS/NICK/USER, JOIN, PRIVMSG, operators vs regular users, KICK, INVITE, TOPIC, MODE (i/t/k/o/l).
  • SCOPE No IRC client of our own, no server-to-server linking.
$ nc -C 127.0.0.1 6667
com^Dman^Dd
$

The subject's own fragmentation test: send a command split in three pieces with Ctrl+D. The server has to reassemble it before treating it as one command — this is exactly what the buffering in #architecture is for.

#who-does-what

Topic: split along the seam that naturally exists — network plumbing vs. IRC logic.
OWNS: sockets, poll loop, buffers, Client class
CLI & bootstrap

Parse ./ircserv <port> <password>, validate the port, fail cleanly on garbage input.

Hint: reject non-numeric ports early. Don't over-engineer validation — just never crash on it.
Listening socket

socket() → setsockopt(SO_REUSEADDR) → bind() → listen(), then set it non-blocking.

Hint: fcntl(fd, F_SETFL, O_NONBLOCK) is the only flag form allowed on macOS per the subject — and it works identically on the school's Linux machines, so use it everywhere.
The single poll() loop

One std::vector<pollfd>: index 0 is the listening socket, the rest are clients. Accept on POLLIN at index 0, read on POLLIN elsewhere, flush on POLLOUT.

Hint: this is the single most graded part of the project. Keep it boring and explicit — full diagram in #architecture.
Per-client buffering

An input std::string per client that accumulates bytes and peels off full lines; an output std::string that queues replies until the socket is writable.

Hint: this is exactly what makes the nc -C fragmentation test pass.
Client class

fd, input/output buffers, registration state (got PASS? NICK? USER?), nickname, username, joined channels.

Disconnection handling

On recv() == 0 or an error: leave all channels, close the fd, erase from the pollfd vector.

Hint: never erase while iterating that vector — collect fds to drop, remove them after the loop.
Low-level command splitting

Turn a raw line into (command, params[]) per IRC grammar, then hand it to Person B's dispatcher.

Where to start A listening socket + poll loop that echoes back whatever it receives — before any IRC logic exists. Test with plain nc.
OWNS: Channel class, command handlers, numeric replies
Channel class

Name, topic, members with an operator flag each, invite list, optional key, optional user limit. Modes: i t k o l.

Hint: a std::map<std::string, Client*> for members makes "is this nick here" and "who's an op" cheap to check.
Registration: PASS, NICK, USER

PASS must match the server password. NICK rejects duplicates (numeric 433). A client only counts as registered once all three landed.

Hint: ignore/queue stray commands politely until registration finishes — don't crash on out-of-order input.
Core messaging: JOIN, PART, PRIVMSG, QUIT

JOIN creates the channel if needed (creator becomes operator), checks invite-only/key/limit. PRIVMSG forwards to every other member of a channel, or to a nick directly.

Hint: always go through Person A's "queue to client's output buffer" helper — never call send() from this layer directly.
Operator commands: KICK, INVITE, TOPIC, MODE

KICK ejects, INVITE lets a user bypass invite-only, TOPIC respects mode t, MODE toggles i t k o l.

Hint: write one isOperator(channel, client) helper and reuse it everywhere instead of repeating the check.
Numeric replies

001 Welcome, 433 nickname in use, 461 not enough params, 442 not on channel, 482 not a channel operator, 332/324 topic/mode, etc. — whatever the reference client expects.

Hint: one formatter — :server <code> <nick> <rest>\r\n — reused everywhere keeps replies consistent.
Command dispatcher

A map from command name to handler function, called by Person A once a full line has been parsed.

Where to start NICK/USER/JOIN/PRIVMSG first — everything else builds on them. Test early against the chosen reference client, not just nc.

Shared contract — agree on this before splitting

A thin Server class ties both sides together. Lock this interface on Day 0 so each side can stub the other and work in parallel.

#architecture

Topic: the shape of the one poll() loop, settled before Server.cpp gets written.

Full detail lives in architecture.md. Here's the shape of it.

1. The loop mechanics

Build the pollfd list → call poll() once → react to whatever came back → clean up after.

build fds = [listening, client1, client2, …]
↓
poll(fds, timeout) — the ONE call
↓ for each fd with revents set
LISTEN · POLLINaccept() a new client, set it non-blocking, push a new pollfd entry.
CLIENT · POLLINone recv(), append to that client's input buffer, peel off full lines.
CLIENT · POLLOUTone send() from that client's output buffer, only when it's non-empty.
revents == 0nothing happened on this fd this round — skip it.
↓
remove disconnected clients — after the loop, never during it

Pitfalls that force a rewrite if missed

⚠ fd reuseA fresh accept() fd is not non-blocking by default — set it yourself, every time.
⚠ iterationNever erase a pollfd entry mid-loop. Collect fds to drop, remove them after.
⚠ stale stateThe OS can hand a closed fd's number to a brand-new client. Fully erase the old Client first.
✓ actually fineChecking errno right after poll() itself (e.g. EINTR) is allowed — the ban is on doing it after recv/send.

2. One client's journey (the fragmented-message case)

The exact scenario the subject's nc -C test checks: "NIC" then "K bob\r\n".

connect()
poll() sees POLLIN on listening fd → accept() → fd 7, set non-blocking
inbuf = ""
send "NIC"
recv(7) → "NIC" (3 bytes), appended — no line terminator yet, wait
inbuf = "NIC"
send "K bob\r\n"
recv(7) → "K bob\r\n", appended — line complete, extract "NICK bob"
inbuf = "" nickname = "bob"
dispatchCommand → queueReply(":server 001 Welcome…") → ask poll() to watch POLLOUT
outbuf = ":server 001 …\r\n"
poll() sees POLLOUT on fd 7 → send() → all bytes left → stop watching POLLOUT
outbuf = ""
receives "001 Welcome bob"

Pitfalls specific to buffering

⚠ more than one lineUse a while, not an if, when pulling lines out — one recv() can deliver several commands at once.
⚠ line endingsSome clients (raw nc) send bare \n. Split on \n, then strip a trailing \r if present.
⚠ partial sendsend() can write less than the whole buffer. Erase only the bytes it actually reported sending.
void handleClientRead(int fd) {
    char buf[1024];
    int n = recv(fd, buf, sizeof(buf), 0); // exactly ONE recv() call

    if (n <= 0) { markForRemoval(fd); return; } // 0 = closed, <0 = error, no retry

    Client &c = *clients[fd];
    c.inbuf.append(buf, n);

    size_t pos;
    while ((pos = c.inbuf.find('\n')) != std::string::npos) {
        std::string line = c.inbuf.substr(0, pos);
        if (!line.empty() && line[line.size()-1] == '\r') line.erase(line.size()-1);
        c.inbuf.erase(0, pos + 1);
        dispatchCommand(c, line);
    }
}

#testing

Topic: things to throw at the server before trusting it, in rough order.
  • 01nc -C 127.0.0.1 <port> fragmented-command test from the subject.
  • 02Two nc clients at once — one sends to a channel, the other receives.
  • 03Reference client: auth with password, set nick/user, join, PRIVMSG both ways.
  • 04Wrong password rejected cleanly.
  • 05Duplicate nickname rejected (433).
  • 06Mid-channel disconnect doesn't crash the server or leave ghosts.
  • 07-Wall -Wextra -Werror -std=c++98 compiles clean.
